# Part I — The Forth

## 1. Overview

ForthJIT is a small, self-contained Forth. It is built from three layers:

1. **A threaded interpreter** (`forth.c`). The dictionary is an array of
   `Word` structures linked through `link`. A colon definition compiles into a
   flat array of cells, `code[]`; each cell is either a pointer to a `Word`
   (an execution token) or inline data (a literal, a branch offset, ...). An
   execution token (xt) is simply a `Word *`.
2. **A native prelude** (`prelude.fs`). Most everyday words (`DUP`, `+`,
   `EMIT`, `.`, `TYPE`, `IF`, ...) are written as `CODE` words or colon
   definitions in the prelude and assembled to machine code at boot through
   SLJIT. The C kernel only keeps the VM, the compiler, byte-memory access,
   I/O, the dictionary, the `CODE` assembler and the dynamic linker.
3. **A call-threaded JIT**. `JIT name` translates a colon body into native
   code that keeps the data-stack pointer in a register and calls prelude words
   directly.

Cells are a C `long` (64-bit on the platforms this targets). There is a single
data stack and a single return stack; both are fixed-size C arrays.

### Build and run

```
make            # build ./forth (normal, optimised)
make test       # run test.fs and test-native.fs
make asan       # build ./forth with AddressSanitizer (overwrites ./forth)
make clean
```

After `make asan`, plain `make` will say "nothing to do" because `forth` is
newer than `forth.c`; run `make clean && make` to get a normal build again.

Run a file with `./forth file.fs`; with no argument it reads the REPL from
stdin. `FORTH_NO_PRELUDE=1` skips the prelude (useful only for debugging the
kernel). The prelude is shipped compressed in `prelude_blob.h`, generated by
`tools/mkprelude`.

Command line: `forth [--require FILE]... [--repl WORD] [FILE]`.
`--require FILE` evaluates `REQUIRE FILE` (repeatable); `--repl WORD` runs the
Forth word `WORD` instead of the built-in REPL (e.g.
`--require scheme.fs --repl SCHEME`).

## 2. Lexical structure

Input is read a line at a time and split into whitespace-separated tokens.
Names are **case-sensitive** and at most 31 characters.

- `\` starts a line comment.
- `( ... )` is an inline comment; it must be closed on the same line.

Both are also ignored inside a `CODE ... ;CODE` body.

Numbers (all integers; there is no floating point in the Forth):

| Spelling | Base | Example |
|----------|------|---------|
| `42`, `-7` | decimal | `42 -7` |
| `$2a` | hex | `$FF` |
| `0x2a` | hex | `0x1F` |
| `%1010` | binary | `%1111` |
| `#42` | forced decimal | `#42` |

Booleans are `TRUE = -1` and `FALSE = 0`. Comparisons return these.

Any token that is not a known word and not a number is an error
(`? name`, throw code `-13`).

## 3. The data stack

Words are listed with their stack effects `( before -- after )`.

| Word | Effect | Notes |
|------|--------|-------|
| `DUP` | `( x -- x x )` | |
| `DROP` | `( x -- )` | |
| `SWAP` | `( a b -- b a )` | |
| `OVER` | `( a b -- a b a )` | |
| `NIP` | `( a b -- b )` | |
| `TUCK` | `( a b -- b a b )` | |
| `ROT` | `( a b c -- b c a )` | |
| `2DUP` | `( a b -- a b a b )` | |
| `2DROP` | `( a b -- )` | |
| `?DUP` | `( x -- x \| x x )` | duplicate if non-zero |
| `DEPTH` | `( -- n )` | number of cells |
| `PICK` | `( ... n -- ... x )` | copy the n-th item |
| `SP@` | `( -- addr )` | current stack pointer |
| `SP!` | `( addr -- )` | reset the stack pointer |

The return stack is separate and is also used by `DO ... LOOP`:

| Word | Effect |
|------|--------|
| `>R` | `( x -- )` move to return stack |
| `R>` | `( -- x )` move from return stack |
| `R@` | `( -- x )` copy top of return stack |
| `2>R` | `( a b -- )` |
| `2R>` | `( -- a b )` |
| `RP@` | `( -- addr )` |

Return-stack misuse raises `-5`.

## 4. Arithmetic and logic

All operations are single-cell.

| Word | Effect |
|------|--------|
| `+` `-` `*` | `( a b -- c )` |
| `/` `MOD` | `( a b -- c )` integer quotient / remainder |
| `NEGATE` `ABS` | `( a -- b )` |
| `1+` `1-` | `( a -- b )` |
| `MIN` `MAX` | `( a b -- c )` |
| `AND` `OR` `XOR` `INVERT` | `( a b -- c )` / `( a -- b )` |
| `LSHIFT` `RSHIFT` | `( a n -- b )` |

`/` and `MOD` raise `-10` on division by zero.

## 5. Comparison

| Word | Effect |
|------|--------|
| `=` `<>` | `( a b -- flag )` |
| `<` `>` `<=` `>=` | `( a b -- flag )` signed |
| `0=` `0<` `0>` | `( a -- flag )` |

Flags are `-1` (true) and `0` (false).

## 6. Output

| Word | Effect | Description |
|------|--------|-------------|
| `.` | `( n -- )` | print signed decimal, then a space |
| `.S` | `( -- )` | print `<depth> a b ...` non-destructively |
| `EMIT` | `( c -- )` | print one character |
| `CR` | `( -- )` | newline |

| `SPACES` | `( n -- )` | print n spaces |
| `TYPE` | `( c-addr u -- )` | print u bytes |
| `." text"` | `( -- )` | print a literal string (compile-time word) |

`.` and `.S` are written in Forth for readability of output; all other output

## 7. Strings and byte memory

`S" text"` leaves `( c-addr u )`. In **interpret** state it returns a buffer
from a ring of eight, so up to eight `S"` strings stay valid at once. In
**compile** state the bytes are copied into the data space and pushed at run
time, so they are permanent.

| Word | Effect | Description |
|------|--------|-------------|
| `MOVE` | `( src dst u -- )` | `memmove` |
| `CMOVE` `CMOVE>` | `( src dst u -- )` | forward / backward byte copy |
| `FILL` | `( c-addr u ch -- )` | fill with a byte |
| `BLANK` | `( c-addr u -- )` | fill with spaces |
| `COMPARE` | `( a1 u1 a2 u2 -- n )` | `-1`, `0`, `1` lexicographic |
| `SEARCH` | `( a1 u1 a2 u2 -- a3 u3 flag )` | substring search |
| `-TRAILING` | `( c-addr u -- c-addr u' )` | drop trailing spaces |
| `/STRING` | `( c-addr u n -- c-addr+n u-n )` | advance a string |
| `>NUMBER` | `( ud c-addr u -- ud' c-addr' u' )` | parse decimal digits |
| `COUNT` | `( c-addr1 -- c-addr2 u )` | counted string → address/length |
| `PLACE` | `( c-addr1 u c-addr2 -- )` | store a counted string |
| `C@` `C!` | `( addr -- c )` / `( c addr -- )` | byte fetch / store |
| `CHAR c` | `( -- c )` | character literal |
| `[CHAR] c` | `( -- c )` | character literal, compiled |

`>NUMBER` accumulates into a double-cell unsigned `ud` (low cell below high
cell) in base 10 and stops at the first non-digit.

```
S" hello world" S" wor" SEARCH . TYPE CR   \ -1 world
S" abcdef" 2 /STRING TYPE CR               \ cdef
: greet S" hi!" TYPE ; greet CR            \ hi!
CREATE buf 64 ALLOT
S" counted" buf PLACE
buf COUNT TYPE CR                          \ counted
```

## 8. Defining words

### Colon definitions

```
: name ... ;
```

`name` is hidden until `;`, so `name` inside the body must be called with
`RECURSE`:

```
: fact DUP 1 <= IF DROP 1 ELSE DUP 1- RECURSE * THEN ;
```

### The compiler kit

These words expose the compiler and let you define your own control-flow or
defining words in Forth:

| Word | Effect | Description |
|------|--------|-------------|
| `HERE` | `( -- n )` | current **code** index (compile pointer) |
| `COMPILE,` | `( xt -- )` | compile an execution token |
| `CODE,` | `( n -- )` | append a raw cell to `code[]` |
| `CODE!` | `( n at -- )` | store a cell into `code[]` at index `at` |
| `CODE@` | `( at -- n )` | read a cell from `code[]` |
| `STATE` | `( -- addr )` | address of the interpreter state cell |
| `[` `]` | | leave / re-enter compile state |
| `LITERAL` | `( x -- )` | compile `x` as a literal |
| `IMMEDIATE` | `( -- )` | mark the most recent definition immediate |

`IF`/`ELSE`/`THEN`/`BEGIN`/`UNTIL`/`AGAIN`/`WHILE`/`REPEAT` are themselves
written in the prelude over this kit; for example:

```
: IF    ['] (0branch) COMPILE,  HERE 0 CODE, ; IMMEDIATE
: THEN  HERE SWAP PATCH ; IMMEDIATE
```

### `CREATE` and `DOES>`

`CREATE name` makes a word that pushes the address of its data field. `DOES>`
(in a defining word) makes the created word push that address and then run a
shared body:

```
: CONSTANT CREATE , DOES> @ ;
```

`VARIABLE name` and `CONSTANT name` are Forth definitions over
`CREATE`/`DOES>`.

### Other defining words

| Word | Description |
|------|-------------|
| `:NONAME ... ;` | compile anonymously; leaves the xt on the stack |
| `POSTPONE name` | compile-time: append `name`'s compilation semantics |
| `[COMPILE] name` | force compilation of an immediate word |
| `DEFER name` | declare a deferred word |
| `IS name` / `ACTION-OF name` | set / read a deferred word's action |
| `SYNONYM new old` / `ALIAS` | make `new` behave like `old` |
| `MARKER name` | define a word that removes itself and later words |
| `FORGET name` | remove `name` and everything after it (dictionary only) |

`MARKER` restores `nwords`, `latest`, `memtop` and `here`; `FORGET` does not
reclaim data or code space.

```
DEFER greet
: hello ." hi" ;
' hello IS greet
greet CR                 \ hi

: plus2 + ;
SYNONYM add2 plus2
1 2 add2 . CR            \ 3
```

## 9. Control flow

### Conditionals

```
IF ... ELSE ... THEN
```

`IF` consumes a flag; the `ELSE` branch is optional.

### Indefinite loops

```
BEGIN ... UNTIL             \ repeat until the flag (consumed) is true
BEGIN ... AGAIN             \ endless; use EXIT / a branch out
BEGIN ... WHILE ... REPEAT  \ one WHILE per BEGIN
```

### Counted loops

```
DO ... LOOP          \ count up by 1
?DO ... LOOP         \ like DO, but skip the body if start == limit
DO ... +LOOP         \ count by the step on the stack
```

`DO` takes `( limit start -- )`. Inside the loop:

| Word | Effect |
|------|--------|
| `I` | `( -- index )` |
| `J` | `( -- outer index )` |
| `LEAVE` | exit the innermost loop immediately |
| `UNLOOP` | drop the loop frame (before an `EXIT` from inside a loop) |
| `EXIT` | return from the current colon definition |

### `CASE`

```
CASE
  1 OF ... ENDOF
  2 OF ... ENDOF
  ... default ...
ENDCASE
```

`CASE` opens the structure, `OF` compares the selector and drops it on a
match, `ENDOF` ends a clause, and `ENDCASE` closes it. A **default** clause goes
just before `ENDCASE`; because `ENDCASE` compiles a `DROP`, a default that
leaves a value must `SWAP` it under the selector first:

```
: ctest CASE 1 OF 111 ENDOF 2 OF 222 ENDOF 333 SWAP ENDCASE ;
1 ctest .   \ 111
3 ctest .   \ 333
```

### Conditional compilation

```
<flag> [IF]
  ...
[ELSE]
  ...
[THEN]
```

`[IF]` consumes a flag; when it is zero the following text is skipped until the
matching `[ELSE]` or `[THEN]`. This spans **multiple lines** and nests. It is
typically used at the top level or with `[ ... ]` inside a definition:

```
0 [IF]
: never-defined ;
[ELSE]
: chosen 42 ;
[THEN]
chosen . CR              \ 42

: ccond [ 1 ] [IF] 10 [ELSE] 20 [THEN] ;
```

## 10. Local variables

Inside a definition, `{ ... }` declares locals:

```
: name { a b -- c } ... ;
```

- Names **before** `--` are inputs, popped from the data stack. The *last*
  name receives the top of stack.
- Names **after** `--` are extra slots initialised to `0` (results).
- All names become local variables for the rest of the definition and shadow
  dictionary words.
- `TO name` stores into a local.
- Each call gets its own frame (saved on the return stack), so locals are
  **recursion-safe**.
- `EXIT` still tears the frame down.

```
: ladd { a b -- c } a b + ;
3 4 ladd . CR            \ 7
: lsum { n -- r } 0 n 0 ?DO I + LOOP ;
10 lsum . CR             \ 45
: lfact { n -- r } n 1 <= IF 1 ELSE n 1- RECURSE n * THEN ;
6 lfact . CR             \ 720
: lstore { a b -- c } a b + TO c c ;
10 20 lstore . CR        \ 30
```

At most 16 locals per definition.

## 11. Memory, variables and constants

There is one flat, **cell-addressed** data space `mem[]`, with 65536 cells
(`MEM_SIZE`). Addresses are raw byte pointers into it (so `addr + 1` points one
byte on, not one cell). The data-space allocation pointer is `memtop`; it is
advanced by `,` (store a cell) and `ALLOT` (reserve cells). `CELLS`
(`n CELLS`) converts a count of cells to bytes.

| Word | Effect | Description |
|------|--------|-------------|
| `@` `!` | `( addr -- x )` / `( x addr -- )` | cell fetch / store |
| `C@` `C!` | byte fetch / store | |
| `,` | `( x -- )` | append a cell to the data space |
| `ALLOT` | `( n -- )` | reserve n bytes |
| `+!` | `( n addr -- )` | add into a cell |
| `VARIABLE name` | | define a one-cell variable |
| `CONSTANT name` | | define a constant |
| `CREATE name` | | define a word pushing its data-field address |

Note that `HERE` returns the **code** index (the compile pointer used with
`CODE,`), not the data-space pointer. `CREATE`/`VARIABLE` use the data space;
the data-space pointer itself is not exposed as a word.

## 12. Error handling and exceptions

`CATCH` and `THROW` implement ANS exceptions:

```
CATCH ( xt -- ... | code )
THROW ( code -- )
```

`CATCH` saves the stacks, runs `xt`, and on success pushes `0`. If `xt` (or
anything it calls) throws, the stacks are restored and the throw code is
pushed. `THROW 0` does nothing.

`ABORT` throws `-1`; `ABORT" text"` (compile-time) throws `-2` with the message
when the flag is non-zero.

| Code | Meaning |
|------|---------|
| `-1` | `ABORT` |
| `-2` | `ABORT"` |
| `-3` | stack overflow |
| `-4` | stack underflow |
| `-5` | return-stack error |
| `-10` | division by zero |
| `-13` | unknown word |
| `-256` | generic (`THROW`, internal errors) |

`ERROR-CODE ( -- n )` and `ERROR-MSG ( -- c-addr u )` read the last error as a
side channel. An uncaught error at top level aborts the current line, prints
the message, and resets the interpreter state.

Native code can raise through `icall &forth_raise` (see
[section 24](#24-require-and-room-guards)).

## 14. Dynamic linking

Native `CODE` bodies can `dlopen` libraries and call their symbols. The IR
provides `dlopen <lib>` / `dlclose <lib>`, and the `&lib::symbol` operand form
opens the library and resolves the symbol at assembly time.

Forth-level words:

| Word | Effect |
|------|--------|
| `DLOPEN` | `( c-addr u -- handle\|0 )` |
| `DLSYM` | `( c-addr u handle -- addr )` |
| `DLCLOSE` | `( handle -- )` |
| `DLERROR` | `( -- c-addr u )` |
| `DLLIBS` | `( -- )` list open libraries |

Closing a library whose symbols were embedded in generated code leaves those
call sites dangling, so use `DLCLOSE` with care.

## 14a. Loading Forth libraries (`INCLUDE` / `REQUIRE`)

| Word | Effect |
|------|--------|
| `INCLUDE name` | evaluate the file `name` (parses the next whitespace-delimited token) |
| `REQUIRE name` | like `INCLUDE`, but only the first time for a given `name` |
| `READ-LINE` | `( -- c-addr u )` one line from stdin; `u = 0` at EOF |

A name is resolved as given, then as `lib/<name>`, then by searching the
colon-separated directories in `$FORTH_PATH`. Included files run in the
current context; `lib/vm.fs` (the bytecode VM) and `lib/scheme.fs` (a minimal
Scheme, with the `SCHEME` REPL) are loaded this way, keeping language runtimes
out of the core prelude.

## 15. Native code and the JIT

Most of the language is the **native prelude**: `prelude.fs` defines everyday
words as `CODE` words and colon definitions, assembled by SLJIT at boot. The
prelude's native words guard their stack arity with `require n` (underflow) and
`room n` (overflow) so that mistakes raise catchable exceptions instead of
corrupting memory.

`JIT name` translates a colon body into native code; `JIT-ALL` does it for
every compilable colon word and returns how many were compiled.

```
: sq DUP * ;
JIT sq
5 sq . CR        \ 25
```

The generated function keeps the data-stack pointer in a register (the same
register ABI as prelude words), inlines literals and `(0branch)`, and uses
native jumps for `IF`/`BEGIN`. C primitives (which use the global stack) are
surrounded by a sync. The result is installed as the word's `native` pointer
with `code = p_native`, so it is indistinguishable from a hand-written `CODE`
word. Bodies containing `DO`/`LOOP`, and colon words called from JIT code, are
handled by the interpreter. The generated code preserves the caller's `ip`, so
JIT and threaded words call each other freely.

`JIT?` reports whether a colon word has been compiled; `NATIVE>` returns its
native code pointer.

# Part II — `CODE` and the native IR

## 16. `CODE ... ;CODE`

`CODE name ... ;CODE` assembles machine code at compile time through SLJIT:

```
CODE sq
  mov R0, [S1-1c]
  mul R0, R0, R0
  mov [S1-1c], R0
;CODE
5 sq . CR            \ 25
```

The body is written in the IR described below, not in Forth. Inside a `CODE`
body, `\` comments and `( ... )` comments are ignored, and the special tokens
`;CODE` and `IR"` are handled by the outer loop.

`CODE` **injects a prologue and an epilogue** so that a native word follows the
Forth calling convention (section 17). The prologue is equivalent to:

```
enter P 4 2 0 P            \ return type P, 4 scratch + 6 float scratch regs,
                           \ 2 saved regs, no locals, one pointer argument
mov S1, R0                 \ S1 = argument = pointer just past the data-stack top
```

and the epilogue is `ret S1`. You therefore do **not** write `enter`/`ret`
yourself in a `CODE` body. If you want locals, put `locals N` as the first line
(before any instruction):

```
CODE example
  locals 16
  ...
;CODE
```

When a function has been defined with `CODE`, its xt behaves like any other
xt: it can be called from the prompt or from `:` definitions.

The `CODE` word stores its IR source (`irbody`) so it can be `inline`d later.

---

## 17. The Forth calling convention

A native word is a function `cell *fn(cell *sp)`:

- **Argument**: the pointer just past the current top of the data stack,
  i.e. `&dstack[sp] + 1`. `CODE` copies it from `R0` into `S1`.
- **TOS** is `[S1-1c]` (the top cell); the second cell is `[S1-2c]`, and so on.
- **Push** writes `[S1]` and then `S1 += 8`:
  ```
  mov [S1], R0
  add S1, S1, #8
  ```
- **Pop** subtracts 8 from `S1` and reads `[S1]`:
  ```
  add S1, S1, #-8
  mov R0, [S1]
  ```
- **Return**: `ret S1` returns the new stack pointer in `R0` (matching the C
  ABI, where a pointer return goes in `R0`).

With the `CODE` prologue, `S1` is the working stack pointer; the available
registers are `R0..R3` (scratch) and `S0..S1` (callee-saved). The incoming stack
pointer arrives in `R0` and is copied into `S1`.

---

## 18. `enter`, `sig`, `locals`, `ret`

These instructions should appear first in a raw function (i.e. one built with
`ASSEMBLE`, which does **not** inject a prologue):

```
enter <ret-type> <scratch> <saved> <local-size> [arg-type ...]
```

- `<ret-type>` and each `<arg-type>` are one of `V` (void), `W` (word),
  `32` (32-bit), `P` (pointer), `F32`, `F64`.
- `<scratch>` and `<saved>` are the number of scratch/saved integer registers;
  add `fscratches`/`fsaveds`/`vscratches`/`vsaveds` before `enter` to reserve
  float/vector registers.
- `<local-size>` is the local stack size in bytes, addressed as `[SP+off]`.
- Argument types are read greedily from the remaining line and combined into
  the SLJIT signature.

```
sig <ret-type> [arg-type ...]
```

sets the signature used by the next `call`/`icall` without re-emitting `enter`.

```
locals <n>
```

reserves local stack. It must come before the body; in `CODE` it is read from
the first line (see section 16).

```
ret [src]
```

returns; with no operand it is `return void`, otherwise it moves `src` into the
return register first.

## 19. Operands

| Form | Meaning |
|------|---------|
| `R0`..`R9` | scratch integer registers |
| `S0`..`S9` | saved integer registers |
| `SP` | stack pointer register |
| `F0`..`F9`, `FS0`..`FS9` | float registers |
| `V0`..`V9`, `VS0`..`VS9` | vector registers |
| `#123`, `#0x1f` | immediate (base 0) |
| `[R1]`, `[R1+8]`, `[S0-16]` | base + offset (bytes) |
| `[S1-1c]`, `[R2+1c]`, `[S1-3c]` | base + offset in cells (`c` = `sizeof(cell)`) |
| `[R1+R2<<3]` | indexed (shift 0..3) |
| `[#123]` | absolute address |
| `&name` | native Forth word, else a dynamic symbol (libc included) |
| `&lib::name` | symbol from a specific library (opened on demand) |
| `@label` | jump target |
| `label:` / `setlabel` | define a label |

## 20. Instructions

### Simple mnemonics

```
mov dst, src                       also: mov.p mov.u8 mov.s8 mov.u16
                                   mov.s16 mov.u32 mov.s32 mov32
clz|ctz|rev dst, src
add|sub|mul|and|or|xor|shl|lshr|ashr|rotl|rotr dst, a, b
                                   add a 32 suffix (add32, ...) for 32-bit
neg dst, src
not dst, src
nop
int3
```

### Data stack

`spush`/`spop`/`sdrop` are sugar for the Forth data stack (through the working
pointer `S1`). They accept a register or an immediate, **never a memory
operand**, so no hidden scratch register is used. They are unrelated to
`asm.push`/`asm.pop`, which use the hardware stack pointer.

```
spush <reg|#imm>    [S1] = src ; S1 += 8       push a cell onto the data stack
spop  <reg>         S1 -= 8 ; dst = [S1]       pop a cell into a register
sdrop [#n]          S1 -= 8 * n                drop n cells (default 1)
```

### Comparisons, flags and selects

```
cmp <cond> a, b, @label            jump if condition
setflags <cond> a, b               set flags for a following `flags`
flags <cond> dst                   dst = 0/1 from the last flags
select <cond> dst, a, b            conditional move
```

Integer conditions: `eq ne lt le gt ge ult ule ugt uge zero nz`
(`lt..ge` are signed; `ult..uge` are unsigned; `zero`/`nz` test for zero).

### Calls, jumps, returns

```
jmp @label
jump <op> @label|#addr
call <operand>     icall <operand>     \ indirect call, using the current sig
icall.reg <operand>                     \ call with register arguments
callw <name>                            \ call a native Forth word
ret [src]
```

`callw name` calls another native word with the Forth ABI: it sets `R0 = S1`,
calls `name`'s native pointer, and stores the returned pointer back into `S1`.
This is the normal way native words call each other.

### Constants

```
const <op> dst, #v                  a rewritable constant
rwconst <name> <op> dst, #v         a named rewritable constant
```

`rwconst` records the constant so it can be patched later by name.

### Labels

```
label: NAME        setlabel NAME     aligned_label <align> NAME
```

### Data and raw bytes

```
db|dw|dd|dq <v>                     emit 1/2/4/8 data bytes (little-endian)
custom <n> <byte>...                emit n raw bytes
```

### Guards

```
require <n>     raise stack underflow if fewer than n cells are present
room <n>        raise stack overflow if n more cells would exceed the stack
```

See section 24.

### Floating point

```
fop1 <op> fd, fs
fop2 <op> fd, fa, fb
fop2r <op> fd, fa, fb
fcmp <cond> fa, fb, @label          cond = feq fne flt fle fgt fge ordered unordered
fselect <cond> fd, fa, fb
fcopy <op> fd, reg
fset32 fd, <float>
fset64 fd, <double>
fmem <type> fd, [mem]
fmem_update <type> fd, [mem]
```

---

## 21. Labels and jumps

A jump records the target name; labels are resolved at the end of assembly, so
forward references are fine. A jump target may also be a raw address with
`#addr` (for `jump`).

`inline`d bodies rename their labels per expansion (section 26), so `@label`,
`label:`, `setlabel` and `aligned_label` names never collide across
expansions.

## 22. The expanded SLJIT surface

For anything not covered by the friendly mnemonics, the full SLJIT API is
reachable. Opcodes can be given as `SLJIT_*` names (all constants are Forth
words) or raw numbers.

```
op0 <op>                    op1 <op> dst, src        op2 <op> dst, a, b
op2u <op> a, b              op2r <op> dst, a, b      op2shift <op> dst, a, b, sh
op2cmpz <op> dst, a, b, @label
ijump <op> addr             opsrc <op> addr          opdst <op> addr
ret_to addr                 opaddr <op> dst, @label  aligned_label <align> NAME
custom <n> <byte>...        jump <op> @label|#addr   setlabel NAME
```

## 23. Symbols and interpreter state

The operand `&name` is resolved as follows: first a native Forth word, then a
dynamic symbol. The IR also resolves a fixed set of interpreter-state symbols
directly, which is how the prelude implements `DEPTH`, `,`, `ALLOT`, `I`, `J`,
`EXIT`, etc.:

| Symbol | C object |
|--------|----------|
| `&dstack`, `&rstack` | the data / return stacks |
| `&mem` | the data space |
| `&sp`, `&rp` | stack / return-stack pointers (`int`) |
| `&memtop` | data-space allocation pointer |
| `&code` | the threaded code array |
| `&here` | compile pointer |
| `&ip` | instruction pointer |
| `&state` | interpreter state |
| `&compiling` | word being compiled |
| `&latest`, `&nwords`, `&dict` | dictionary |
| `&forth_find`, `&forth_latest`, `&forth_link`, `&forth_name`, `&forth_flags`, `&forth_code`, `&forth_native`, `&forth_data`, `&forth_body_start`, `&forth_body_end`, `&forth_body` | dictionary helpers |
| `&forth_immediate`, `&forth_hidden`, `&forth_colon_p`, `&forth_native_p`, `&forth_variable_p` | predicates |
| `&forth_need`, `&forth_room`, `&forth_raise`, `&forth_divzero`, `&forth_type` | runtime helpers |
| `&putchar`, `&strlen`, ... | libc symbols (via `&name`) |

Example (the prelude's `EXIT`):

```
CODE EXIT
  mov R0, &rp
  mov.u32 R1, [R0]
  add R1, R1, #-1
  mov32 [R0], R1
  mov R2, &rstack
  shl R1, R1, #3
  add R2, R2, R1
  mov R1, [R2]
  mov R2, &ip
  mov [R2], R1
  mov R0, S1
;CODE
```

## 24. `require` and `room` guards

Native words in the prelude begin with a guard so that stack mistakes raise a
catchable error instead of reading or writing out of bounds:

```
require <n>     \ error if DEPTH < n
room <n>        \ error if DEPTH + n > STACK_SIZE
```

Both compute `DEPTH` (from `S1 - &dstack`) and call `&forth_need` / `&forth_room`,
which raise `-4` (underflow) and `-3` (overflow) respectively. They also work
inside JIT-generated code.

```
CODE DUP
  room 1
  mov R0, [S1-1c]
  mov [S1], R0
  add S1, S1, #8
  mov R0, S1
;CODE
```

## 25. Raw emission (`asm.*`)

For instructions SLJIT does not expose, raw bytes can be emitted. On x86-64 the
following mnemonics accept SLJIT registers (`R0`..`R9`, `S0`..`S9`, `SP`) or
physical names (`RAX`..`R15`, `RDI`, ...), resolving them through
`sljit_get_register_index`:

```
asm.mov <dst> <src>        mov r64, r64
asm.mov.imm <dst> <v>      mov r64, imm64     (v = #imm | &sym | number)
asm.call <reg>             call r64
asm.push <reg> / asm.pop <reg>
asm.mov.al <imm8>          mov al, imm8
asm.ret / asm.nop / asm.int3
```

`ARCH` is the target architecture code:

| Value | Architecture |
|-------|--------------|
| 1 | x86-64 |
| 2 | x86-32 |
| 3 | ARM64 |
| 4 | ARM32 |
| 5 | RISC-V 64 |
| 6 | RISC-V 32 |
| 7 | MIPS |
| 8 | PowerPC |
| 9 | s390x |
| 10 | LoongArch |

The `asm.*` mnemonics are only defined on the matching architecture.

Raw emission is what makes **variadic C calls** correct. `sljit_emit_icall`
cannot set `AL` (on x86-64 `SLJIT_R0` is `RAX`), so place arguments in the ABI
registers yourself and set `AL` last:

```
CODE printf1 ( fmt value -- )
  mov R3, &printf        \ function address in RCX
  mov R2, [S1-2c]        \ format  -> RDI
  mov R1, [S1-1c]         \ value   -> RSI
  add S1, S1, #-16
  asm.mov.al 0           \ AL = 0 vector registers
  asm.call R3
  mov R0, S1
;CODE
S" value=%ld" DROP 42 printf1 CR   \ value=42
```

Raw emission inserts bytes into SLJIT's stream; it is an escape hatch, not a
replacement for an assembler (SLJIT still owns layout and jump resolution).

## 26. `inline` and `callw`

```
inline <name>
```

splices the stored IR body of another `CODE` word into the current one, with
**no call**. Labels in the inlined body are renamed per expansion, so a word can
be inlined several times safely.

```
CODE 2DUP
  inline OVER
  inline OVER
;CODE
```

Use `inline` for small words (removes call indirection, duplicates code) and
`callw <name>` for larger ones (a real indirect call, section 20).

## 27. IR as a string

`S" ..."` returns `( c-addr u )`. `ASSEMBLE` compiles the string as IR (with
**no** injected prologue or epilogue) and returns the code pointer. `NATIVE`
turns that pointer into a named word:

```
S" enter P 4 2 0 P mov S1 S0 mov R0 [S1-1c] add R0 R0 #100 mov [S1-1c] R0 ret S1"
   ASSEMBLE NATIVE plus100
7 plus100 . CR        \ 107
```

Inside `CODE`, `IR" ..."` embeds an IR fragment at that point in the body:

```
CODE f
  IR" mov R0, [S1-1c]  add R0, R0, #1  mov [S1-1c], R0"
;CODE
```

`'` pushes a word's xt; `CODE-ADDR` converts it to the C code pointer for use
with `icall` (e.g. `C-PUTCHAR` pushes the address of libc `putchar`).

## 28. Runtime patching

Jump and constant targets can be recorded by name and patched after assembly:

```
rwjump NAME <op> @label     a rewritable jump
rwconst NAME <op> dst, #v   a rewritable constant
```

Forth-level:

```
SET-JUMP-ADDR ( c-addr u target -- )   patch a rwjump by name
SET-CONST     ( c-addr u value -- )    patch a rwconst by name
```

`JIT-SIZE` returns the size of the last generated block and `CPU-FEATURE?`
queries SLJIT's CPU feature flags.

## 29. Worked examples

A native `OVER` and a `2DUP` built from it:

```
CODE OVER
  mov R0, [S1-2c]
  mov [S1], R0
  add S1, S1, #8
  mov R0, S1
;CODE

CODE 2DUP
  callw OVER
  callw OVER
;CODE
```

A native decrement-by-100 in IR-as-a-string (no Forth prologue):

```
S" enter P 4 2 0 P mov S1 S0 mov R0 [S1-1c] sub R0 R0 #100 mov [S1-1c] R0 ret S1"
   ASSEMBLE NATIVE minus100
```

String output through a libc call with a register-set `AL` (section 25).

## 30. Limits

The interpreter's dynamic structures grow on demand, so the old fixed-size
arrays are gone:

| Structure | Storage | Meaning |
|-----------|---------|---------|
| Dictionary | arena (malloc'd blocks) | `Word` nodes linked from `LATEST` |
| Code space | growable buffer (`realloc`) | threaded `code[]` cells |
| Data space | reserved region (grow by page commit) | `CREATE` bodies, `,`/`ALLOT`, string literals |
| Data stack | reserved region (grow by page commit) | data stack cells |
| Return stack | reserved region (grow by page commit) | return stack cells |

Remaining bounded constants:

| Constant | Value | Meaning |
|----------|-------|---------|
| `NAME_LEN` | 32 | bytes per name (31 chars + NUL) |
| `MAX_LOCALS` | 16 | locals per definition |
| `LOCALS_MAX` | 4096 | local-frame slots in total |
| `MAX_XFRAME` | 64 | nested `CATCH` frames |
| `IRBUF_SIZE` | 65536 | IR source buffer |
| `MAX_IRTOK` | 8192 | IR tokens per body |

Memory is obtained with `MALLOC`/`REALLOC`/`FREE` (libc) and with `ALLOC`
(a stable-address arena; `ARENA-RESET` releases it administratively without
returning pages to the OS). `,`/`ALLOT` bump the data region.

- Cells are 64-bit; all Forth arithmetic is single-cell integers.
- There is no floating point in the Forth (SLJIT float support is reachable
  only through the IR).
- The backend is SLJIT; only the `sljitLir.c` file is compiled, so the
  architecture is fixed at build time (`ARCH` reports it).
- Dictionary lookup is case-sensitive.
- `FORGET`/`MARKER` drop dictionary nodes; the arena memory is reclaimed
  administratively (not returned to the OS).
